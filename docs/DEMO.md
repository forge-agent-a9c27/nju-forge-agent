# 两分钟演示方案

目标是展示一次真实“发现问题—修改—验证—总结”，不要只展示聊天或预先写好的成功答案。仓库已经附带可重复重置的原子库存演示任务。

## 一键准备演示项目

在仓库根目录运行：

```powershell
python scripts/prepare_video_demo.py --force
Set-Location .forge\video-demo
python -m unittest -v
Set-Location ..\..
```

基线应为 4 项测试、3 项失败：跨商品库存不足、未知商品会造成部分扣减，布尔值被错误当作整数。这个失败画面可以录入视频，证明修复并非预置。

录制前再次运行 `python scripts/prepare_video_demo.py --force` 即可恢复原始 bug。不要把 `.forge` 加入 Git，它已被忽略。

## 录制前

1. 把公开仓库地址填入 `README.txt`，确认工作区无任何真实凭据和 `.forge` 目录。
2. 运行上面的准备脚本；先执行一次测试，确认显示 `FAILED (failures=3)`。
3. 在录屏区域外设置模型相关环境变量。关闭会显示环境变量、历史命令或通知的窗口。
4. 终端字号调大，执行 `python agent.py -w <示例项目>`。使用默认 `ask` 模式。

## 录制命令

环境变量必须提前设置好，开始录制后先执行 `Clear-Host`，不要展示凭据。为减少文字和时间，不加 `--show-reasoning`。使用一整行命令，避免 PowerShell 续行符被复制错误：

```powershell
python agent.py --workspace ".forge\video-demo" "阅读 TASK.md 和测试，修复 inventory.py 中库存预留的原子性与输入校验问题；必须运行全部测试验证，不要修改测试。完成后简要说明根因和验证结果。"
```

## 精确时间轴与讲稿

- 0:00–0:10：展示第一次测试的 3 个失败。旁白：“这是一个真实的库存预留 bug，失败请求会留下部分扣减。”
- 0:10–0:20：回到仓库根目录并输入上面的 Forge 命令。旁白：“Forge 不依赖 Agent SDK，模型负责决策，本地程序负责工具执行与安全边界。”
- 0:20–1:12：展示 `update_plan`、`list_files`、`read_file`、`edit_file` 和 `run_command`。接口等待段可以加速，工具名称和 `OK` 结果至少保留一秒可读。
- 1:12–1:30：停留在测试从失败变为 `OK` 的画面。旁白：“Agent 先完整校验再统一扣减，并额外处理了 Python 中 bool 是 int 子类的边界。”
- 1:30–1:48：展示最终总结和编辑事务号。旁白：“每次编辑使用原子替换、版本哈希和可回滚 journal；命令按风险分级。”
- 1:48–2:00：展示 GitHub 仓库首页或项目测试结果。旁白：“29 项离线测试覆盖模型协议、上下文、工具、安全和完整 CLI 链路。”

若模型输出过长，在视频中只保留工具执行和最终验证；允许剪辑及加速，但不要伪造调用或删除失败信息。若一次运行失败，执行准备脚本的 `--force` 后重录。

## 讲解要点

只讲三层：模型产生结构化决策；自研循环把结果写回上下文并决定继续/停止；工具层负责真实执行与确定性安全边界。强调命令分类不是沙箱、确定性摘要的取舍、SHA-256 乐观锁如何避免覆盖用户并行修改。视频必须小于 200 MB、mp4 格式；剪辑和加速可以使用，但不展示任何凭据。

## 最终打包

将公开仓库地址写入 `README.txt` 后执行：

```powershell
python scripts/package_submission.py --name "你的姓名" --video D:\path\demo.mp4
```

脚本会检查 README 汉字数和公开仓库链接、mp4 签名、200 MB 限制，并在系统装有 `ffprobe` 时检查两分钟限制。生成的 `submission/你的姓名.zip` 经二次读取确认只含 README 和视频；已有同名文件时脚本拒绝覆盖。
